# Report Schema

Reference for the JSON report format generated by semverguard.

## Overview

When JSON output is enabled, semverguard produces a structured report containing:

- Run metadata (timestamps, version)
- Per-package results
- Summary statistics

## Top-Level Structure

```json
{
  "semverguard_version": "0.1.0",
  "started_at": "2024-01-15T10:00:00Z",
  "finished_at": "2024-01-15T10:01:30Z",
  "workspace_root": "/path/to/workspace",
  "packages": [...],
  "summary": {...}
}
```

### Fields

| Field | Type | Description |
|-------|------|-------------|
| `semverguard_version` | string | semverguard CLI version |
| `started_at` | string | ISO 8601 timestamp (UTC) when run started |
| `finished_at` | string | ISO 8601 timestamp (UTC) when run finished |
| `workspace_root` | string | Absolute path to workspace root |
| `packages` | array | Per-package results (see below) |
| `summary` | object | Aggregate counts (see below) |

## Package Entry

Each entry in the `packages` array:

```json
{
  "name": "my-lib",
  "version": "1.2.3",
  "manifest_path": "/path/to/my-lib/Cargo.toml",
  "status": "passed",
  "skip_reason": null,
  "duration_ms": 1234,
  "command": ["cargo", "semver-checks", "check-release", "--manifest-path", "..."],
  "engine": {...},
  "inferred_required_bump": null
}
```

### Fields

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Package name from Cargo.toml |
| `version` | string | Package version |
| `manifest_path` | string | Path to package's Cargo.toml |
| `status` | string | Result status (see below) |
| `skip_reason` | string \| null | Why package was skipped (if status = "skipped") |
| `duration_ms` | number | Check duration in milliseconds |
| `command` | string[] | Command executed (empty if skipped) |
| `engine` | object \| null | Engine output details (see below) |
| `inferred_required_bump` | string \| null | Required version bump level |

### `status` Values

| Value | Description |
|-------|-------------|
| `"passed"` | SemVer check passed, no breaking changes |
| `"failed"` | SemVer check failed, breaking changes detected |
| `"skipped"` | Package was filtered out by policy |

### `skip_reason` Examples

When `status = "skipped"`, this explains why:

- `"publish = false"` - Package has `publish = false` in Cargo.toml
- `"no library target"` - Package has no lib target
- `"filtered by include/exclude patterns"` - Didn't match scope.include or matched scope.exclude
- `"unchanged relative to origin/main"` - No changes detected in changed mode

### `inferred_required_bump` Values

| Value | Description |
|-------|-------------|
| `"patch"` | Patch bump required |
| `"minor"` | Minor bump required |
| `"major"` | Major bump required |
| `"unknown"` | Bump required but level unclear |
| `null` | No bump required or not applicable |

This is inferred from cargo-semver-checks output and may not always be present.

## Engine Output

When a package is checked (not skipped), the `engine` field contains:

```json
{
  "exit_code": 1,
  "success": false,
  "stdout": "...",
  "stderr": "...",
  "required_bump": "major"
}
```

### Fields

| Field | Type | Description |
|-------|------|-------------|
| `exit_code` | number \| null | Process exit code (null if killed by signal) |
| `success` | boolean | Whether the check passed |
| `stdout` | string | Captured standard output |
| `stderr` | string | Captured standard error |
| `required_bump` | string \| null | Bump level from engine output |

## Summary

```json
{
  "total": 5,
  "passed": 3,
  "failed": 1,
  "skipped": 1
}
```

### Fields

| Field | Type | Description |
|-------|------|-------------|
| `total` | number | Total packages in report |
| `passed` | number | Packages that passed |
| `failed` | number | Packages that failed |
| `skipped` | number | Packages that were skipped |

Invariant: `total == passed + failed + skipped`

## Parsing Examples

### jq

```bash
# Get failed package names
jq -r '.packages[] | select(.status == "failed") | .name' report.json

# Get summary
jq '.summary' report.json

# Check overall success
jq '.summary.failed == 0' report.json

# Get all required bumps
jq '.packages[] | select(.inferred_required_bump != null) | {name, bump: .inferred_required_bump}' report.json
```

### TypeScript

```typescript
interface Report {
  semverguard_version: string;
  started_at: string;
  finished_at: string;
  workspace_root: string;
  packages: Package[];
  summary: Summary;
}

interface Package {
  name: string;
  version: string;
  manifest_path: string;
  status: 'passed' | 'failed' | 'skipped';
  skip_reason: string | null;
  duration_ms: number;
  command: string[];
  engine: EngineOutput | null;
  inferred_required_bump: 'patch' | 'minor' | 'major' | 'unknown' | null;
}

interface EngineOutput {
  exit_code: number | null;
  success: boolean;
  stdout: string;
  stderr: string;
  required_bump: string | null;
}

interface Summary {
  total: number;
  passed: number;
  failed: number;
  skipped: number;
}
```
